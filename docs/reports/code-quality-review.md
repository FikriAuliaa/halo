## Layering

`grep -rn "canTransition\|assertTransition" src/server/repositories` returns nothing — no status-transition rule lives in a repository (confirmed originally in the Phase 6 gate, re-confirmed here). Reservation- and order-lifecycle decisions live in `src/server/operations/*` and `src/domain/*`; nothing reservation- or order-specific has leaked into `src/components`.

## Documentation currency

`AGENTS.md` and `SECURITY.md` both carried Firebase/Firestore-era prohibitions and descriptions well past the mid-build migration to Supabase/Postgres. `SECURITY.md` was substantially rewritten in Phase 14. Two remaining stale bullets in `AGENTS.md`'s prohibited-patterns list (a `FirestoreDataConverter` rule, an "optimistic transaction" rule) were corrected in this pass to their real Postgres equivalents rather than left under the blanket "any surviving Firestore reference is stale" disclaimer already at the top of the file — a disclaimer is a safety net, not a substitute for fixing what it's excusing.

`RUNBOOK.md` §6 ("Unreachable Firestore") was already corrected in Phase 16. §3 ("Wrongly-verified order") still describes a manual-correction capability (`adminOverrideOrderStatus`) that was never implemented — see `docs/reports/traceability-matrix.md` and `docs/reports/security-review.md`, both of which already flag this; not re-fixed here to avoid three reports converging on the same edit mid-review.

## Verdict

No prohibition is actively violated. The one hardcoded-string hit is in a dev-only, production-unreachable page and is a reasonable, low-risk exception rather than a defect. The documentation-currency gaps found are all now either fixed (`AGENTS.md`'s two bullets, `RUNBOOK.md` §6) or explicitly tracked for the remediation pass (B139): the three unimplemented admin operations `RUNBOOK.md` §3 still assumes exist.
