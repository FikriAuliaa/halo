| 2026-08-22 | Sign-in and session-refresh moved off the shared service-role Supabase client onto a scoped, throwaway one (`createScopedAuthClient`). | Live bug: `signInWithPassword`/`refreshSession` mutate whatever client they're called on; on the shared client this silently poisoned every later Storage call in the process to authenticate as the logged-in admin instead of service_role, surfacing as "Object not found" for files that demonstrably existed. | Phase 10-11 gate | Yes — internal refactor, no external contract change |
| 2026-08-22 | `orderFormSchema` split into `personalDataFormSchema` (the four fields the `/data` screen actually collects) plus `package_id`. | Live bug, found by real E2E browser testing: the `/data` screen validated its draft against the full schema, which also requires `package_id` — a field that screen never collects — so submission always failed silently and no student could complete an order through the real UI at all. | Phase 15 gate | Yes — schema/validation-only, no data model change |
| 2026-08-22 | `(admin)/(dashboard)/layout.tsx` wrapped in `ToastProvider`. | Live bug: every admin screen calling `useToast()` (essentially all of them) crashed with a 500 on render, undetected because Phases 10-13's verification was API-route-only and never actually rendered these pages in a browser. | Phase 15 gate | Yes — layout-only |
| 2026-08-22 | Phase 14's CSP allows `'unsafe-eval'` in `script-src` only when `NODE_ENV !== "production"`. | Live bug: an unconditional strict CSP blocked Next.js dev-mode's own module evaluation, silently breaking all client-side JS in dev (production was unaffected, confirmed via a real `next build && next start`). | Phase 15 gate | Yes — security-header config only |
| 2026-08-22 | E2E test data cleanup moved from a shared wildcard `afterAll` to per-test ownership; admin logins consolidated into a `global-setup.ts` using saved `storageState`. | Test-infrastructure bugs, not app bugs: the wildcard cleanup ran per-worker under `fullyParallel`, letting a fast-finishing spec file delete another file's still-in-use test data; repeated per-test admin logins across files collided with the intentionally tight admin-login rate limit once the full suite ran together. | Phase 15 gate | Yes — test-only |
| 2026-08-22 | `createHandler`'s GET query-string parsing rebuilt to group repeated keys into arrays (`parseQueryParams`); `getAvailableNumbersQuerySchema` normalizes a lone `exclude` value into a one-element array too. | Live bug, found by a real user clicking "Refresh": `Object.fromEntries(searchParams)` silently keeps only the last value for a repeated key, so `?exclude=a&exclude=b` became `{ exclude: "b" }` — and even a single `exclude` value failed too, since a bare string was never a valid `z.array`. Every refresh past the very first page load hit this. | (found live, not a numbered block) | Yes — parsing/schema fix, no API contract change for callers already sending a real array |
| 2026-08-22 | Package price display changed from "Rp {price/1000} ribu" to the full formatted amount ("Rp 100.000"), matching the smaller price line already on the same card. | Requested by the user — the abbreviated form read inconsistently against the "Rp100.000 / bulan" line directly below it on the same card. | (found live, not a numbered block) | Yes — display-only |
| 2026-08-22 | The non-interactive "Pilih 1 Extra Benefit" chip removed entirely from the package screen (OQ-3). | A real user found the chip confusing — it visually reads as a selectable pill but has never done anything, since no benefit catalogue was ever defined (spec gap, OQ-3). Removing it is less confusing than a chip that looks tappable and isn't. | (found live, not a numbered block) | Yes — re-add alongside a real benefit catalogue if one is ever defined |
| 2026-08-22 | `normalizePhone` accepts a bare national significant number with no leading `0` or `62` (e.g. `"812..."`); `PhoneField` now re-displays its value stripped of any `0`/`62` prefix rather than in the shared "08..." convention. | Live bug, found by a real user: the field renders a fixed, non-removable "+62" prefix, so typing directly after it (as the UI invites) produced exactly the input this fix now accepts — the old code rejected it outright, and even on a value it did accept, re-displayed it in a form that would have doubled up with the fixed prefix (e.g. "+62081234567890"). | (found live, not a numbered block) | Yes — parsing/display fix only, storage format (`+628...`) unchanged |
| 2026-08-22 | "Simpan QR" on the payment screen now `fetch()`s the QRIS image itself and downloads it via a `blob:` URL, instead of a plain `<a download href="...">` pointing straight at the Supabase Storage URL; CSP's `connect-src` extended to the same Supabase origin already trusted by `img-src`. | Live bug, found by a real user: every browser silently ignores the `download` attribute for a cross-origin `href` — clicking it just opened the image instead of saving it. Fetching it client-side into a same-origin `blob:` URL is the actual fix; that fetch was then blocked by `connect-src` not yet trusting the same origin `img-src` already does. | (found live, not a numbered block) | Yes — CSP directive addition and a component-local change, no data/API contract change |
| 2026-08-22 | Proof-upload "Coba Lagi" now clears the file and returns to the pickable state for a file-inherent rejection (`INVALID_FILE_TYPE`, `FILE_TOO_LARGE`), instead of resubmitting the identical file; the uploader's default hint corrected to "Format JPG, PNG, WEBP" (it always accepted WEBP, the hint just never said so). | Live bug, found by a real user: `onRetry` called `submit()` directly, which re-sent the exact same rejected file — for a bad-content error that's deterministic, so it failed identically forever, appearing "stuck." Only genuinely transient failures (network errors, 5xx) are worth resubmitting as-is. | (found live, not a numbered block) | Yes — client-side retry logic and hint text only, no API/schema change |

Further entries are appended as later phases make additional cheap-to-reverse calls (e.g. component-library choices within `DESIGN.md`, exact rate-limit thresholds). ADR-numbered decisions are not duplicated here.
